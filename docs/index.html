Every other NTFS driver on macOS ships a kernel extension — or copies your files byte-by-byte in userspace. NTFSKit does neither: the kernel writes your data directly to disk, while the driver just maps the blocks.

01

How the write path works

Legacy drivers (Paragon · Tuxera · FUSE)

01App writes to the mounted volume
02Kernel extension (or FUSE bridge) intercepts
03Bytes copied through the driver's own code
04Driver writes them out to the device
→ kext risk, or ~1–20 MB/s in userspace

NTFSKit · Kernel-Offloaded I/O

01App writes to the mounted volume
02Driver maps the file's on-disk extents
03Kernel writes data directly to those blocks
04Driver only stamps the metadata
→ device-speed writes, userspace safety
